# Atlas of Wisdom — repo notes

Third app of the Great Harmony suite (with `words-of-sages` and
`Journey-To-Great-Harmony`). It **complements** the other two apps — shared
antique-atlas aesthetic (Cinzel + Noto Serif, parchment/ink/gold) and a
distinct "explore when curious" niche — but has **no cross-app integration**
(no shared links, XP or accounts) by design.

## Token efficiency (do not violate)

Be frugal with tokens/context in every session: don't re-read files already
read; prefer targeted Grep/Read over whole-file reads (the `src/data/locations/*`
files are large); don't spawn subagents for lookups doable in 1–2 tool calls;
verify with the smallest sufficient check.

## i18n rule (do not violate)

Every user-facing string must follow the chosen language (English /
Simplified Chinese / Traditional Chinese):

- UI chrome goes through `t('key')` — add keys to `UI` in `src/i18n/strings.ts`.
  Never write a raw string literal into JSX.
- Content data (locations, people, collections, achievements, ranks) is
  `Localized<T>` (`src/i18n/types.ts`), authored in **English + Simplified
  Chinese**, rendered via `L(field)` from `useT()`.
- Traditional Chinese is **generated**: run `npm run gen:i18n` after any
  content change and commit `src/i18n/zhHant.generated.json`. The script
  (`scripts/gen-zh-hant.ts`) scans all data roots — add new data modules to
  its import list when created.
- Sanity-check user-facing changes in all three languages before shipping.

## Data model

- Locations live in `src/data/locations/*.ts` (one file per world region),
  aggregated in `src/data/locations.ts`. Schema: `src/data/types.ts`
  (`AtlasLocation`). `period` uses signed years (negative = BC) — kept for
  the future Time Explorer module.
- Collections (`src/data/collections.ts`) are **predicates** over locations —
  new locations automatically join matching collections. The nine virtue
  collections are generated from `VIRTUES`, so adding a virtue adds a
  collection for free.
- Every location carries 1–3 `virtues` (`src/data/virtues.ts`). These power
  the cross-tradition virtue collections, the post-story reflection prompt,
  and the Virtue Compass on the Profile page — the app's "spiritual journey"
  thread. Virtues are chosen to cut *across* traditions on purpose (a
  Confucian academy and a Sufi shrine can both be Places of Wisdom); they
  describe a place's story and must never read as ranking traditions.
  `validate-data` enforces 1–3 per place, no duplicates, and ≥3 places per
  virtue so no collection is trivially completable.
- Achievements check derived `ExplorationStats` only (`src/data/achievements.ts`).
- `npm run validate-data` (also runs pre-build) checks id uniqueness, coord
  ranges, timeline order, en/zh paragraph parity, and person↔location
  cross-refs. Keep it green.

## Content voice (the differentiator)

`whyItMatters` is 2–3 short, story-like paragraphs in plain language — a
guide telling a story, never an encyclopedia entry. Same neutral, respectful
framing for every tradition. All-ages readable. Timelines: 2–6 events,
chronological, signed years.

## Architecture notes

- React 18 + Vite + TS PWA, HashRouter (no server rewrites needed), zustand
  `persist` stores in localStorage — **no backend**. Stores are deliberately
  separate: `atlas-locale` (language) survives `atlas-progress` resets.
- Daily features (Discovery of the Day, 3-question quiz) are deterministic
  date-seeded picks (`src/engine/daily.ts`) — no server needed. Quiz questions
  are generated from location data (`src/engine/quiz.ts`), options
  mastery-gated (wrong answers don't advance).
- XP/unlock granting happens inside `src/state/store.ts` (`collectUnlocks`);
  toasts go through the non-persisted `toastStore`. Every action builds a
  mutable `snapshot(state)`, mutates what it changed, runs `collectUnlocks`,
  then `set()`s — add new progress fields to `Snapshot`/`emptyState` so all
  actions carry them forward rather than silently dropping them.
- Reflections (`submitReflection`) are private, stored locally, never scored,
  and gated on `MIN_REFLECTION_CHARS` — the same minimum-effort idea as
  Journey's capstones. Keep them un-graded; the point is honesty, not output.
- Map: MapLibre GL, globe projection, **fully offline**. There is no tile
  server: `src/components/map/offlineStyle.ts` is a self-contained style over
  bundled GeoJSON (`public/geo/`) generated by `npm run gen:basemap` from
  Natural Earth 1:10m (public domain — countries, admin-1, rivers, lakes,
  populated places, major roads, physical-feature names) — ~13 MB, precached
  by the service worker. Regenerate only if you change the source resolution;
  the output is committed. Country/admin-1/river label anchors use a real
  visual-center (pole-of-inaccessibility) calculation in `gen-basemap.ts`,
  not a plain vertex average — needed because antimeridian-crossing countries
  (Russia, USA, Fiji) collapse a naive average toward 0° longitude.
  `npm run validate-data` runs MapLibre's own style validator plus a check
  that each referenced GeoJSON/raster source exists, so a broken basemap
  fails the build rather than showing users a blank globe.
- A subtle shaded-relief terrain texture sits under the flat land tint,
  generated by `npm run gen:relief` (`scripts/gen-relief.ts`) from Natural
  Earth's public-domain raster: downloads once (cached under
  `scripts/data/ne/`), reprojects the equirectangular source into a small
  local Web Mercator XYZ tile pyramid (`public/geo/relief/{z}/{x}/{y}.jpg`,
  z0–3, no tile server), and tints it toward the parchment/gold palette.
  Regenerate only if you change its resolution/tint; the tiles are committed.
- Label placement in `GlobeMap.tsx` is real collision-based layout, not a
  flat per-tier count cap: each candidate (cluster count > curated place >
  country > city > river > admin-1 > physical feature, in that priority
  order) reserves a canvas-`measureText()`-sized screen box and is skipped if
  it would overlap a box already claimed this frame. A removed-label DOM node
  tolerates one missed frame before actually unmounting, smoothing over
  MapLibre's `queryRenderedFeatures`/`querySourceFeatures` timing gaps during
  continuous drag/rotate.
- The style deliberately has **no `glyphs` URL and no symbol layers** — glyph
  PBFs need a server and a CJK set would be megabytes. All map text (cluster
  counts, place labels) is an HTML overlay in `GlobeMap.tsx`, positioned with
  `map.project()` from `queryRenderedFeatures` on move, which also renders
  Chinese and emoji using the app's own fonts. Don't reintroduce symbol
  layers without solving glyphs first.
- Sources/layers are added on `style.load`, not `load`: `load` waits for a
  first paint, which never happens while a tab is backgrounded (MapLibre's
  render loop is rAF-driven). This also means the map cannot be verified in
  a headless/hidden browser pane — it will never fire `load` or even parse an
  inline style there. Verify the map on a real visible screen.
- Marker layers are rebuilt via `setData` on filter/locale change.

## Deferred by design (phase 2+)

Figure journeys (Module 2), expeditions (3), time slider (8), quests/hidden
objects (5/6), compare (9), knowledge graph (10), community, photo galleries
(schema has no images yet — imagery via Wikimedia Commons is the planned
approach). Location↔person cross-links already exist so Module 2 needs no
data migration.
